# 실제 응답 표본 검증 결과 (단계 3)

- 실행: `node --import ./scripts/ts-register.mjs scripts/eval.mjs` (원문은 eval-out/에 저장, gitignore)
- **API 호출: 127회 / 한도 140회** (처음 한도 80회, 사용자가 60회 추가 승인. 마지막 결정 반영 확인은 회차 상한 20회 중 14회). 호출 간격 3초, 429는 한 번도 없었음.
  - 1차 전체 64회 → 1회차 수정 후 4회 → 2회차 10회 → 첫 세트 단순화 확인 1회 → 초급 다시 받기 확인 1회(80/80)
  - 한도 추가 후: 실패 표본·비교 표본 19회 → 3회차 수정 후 10회 → 단순화 확인 4회(113/140)
- 판정은 두 겹: ① 스크립트 자동 검사(형식·어절 상한·금지 어휘·내부 표시·{{n}}·세트 간 중복·초급 상대역 검사) ② Claude Code가 품질 채점표 6항목(1 문법성, 2 화용, 3 난이도, 4 논리 일관성, 5 형식, 6 교육적 타당성)을 모두 확인. 한 항목이라도 미달이면 불합격.
- 표의 판정은 각 표본의 **마지막 생성본** 기준. 초급 상대역 말은 화면과 같이 1회 다시 받기를 적용해 평가했고, 도움(hint·frame·choices·model·starter)은 화면의 자동 재요청 없이 **첫 응답만** 평가했으므로 실제 화면보다 엄격함.
- 판정 기준 변경: 사용자 결정으로 '방법'·'의견'·'생각'을 초급 어휘로 옮김. 이전에 '방법' 때문에 불합격으로 본 발화는 다른 문제로만 판정함.

## 초급 다시 말하기 안내 비교 (회의 반대 의견·초급, 상대역 첫 대답, `simplify: true`)

| 안내 | 다시 받은 말 | 현재 기준 검사 |
|---|---|---|
| 이전: 금지 명사 목록을 적은 안내 | "네, 말씀 잘 들었어요. 어떤 방법이 좋을까요?" | 통과('방법'은 초급 어휘로 바뀜) |
| 현재: 쉬운 질문 꼴 안내 | "네, 돈이 많이 드는군요. 다른 방법도 있어요?" | '-군요'(3권) 1건 |

- 질문은 안내대로 쉬운 꼴("다른 방법도 있어요?")이 되었지만 '-군요'가 다시 나와, 이 한 번의 비교로는 **효과가 있다고 볼 수 없음**. 각 1회 표본이라 차이가 우연일 수 있음.
- 같은 차례를 실제 화면 흐름(처음 받기 → 검사 → 다시 받기)으로 돌린 D 표본에서는 처음 말("…걱정되시는군요…")이 걸린 뒤 다시 받은 말 "네, 알겠습니다. 다른 방법이 있어요?"가 통과함.

## 결정 반영 확인 (14회)

| 확인 항목 | 표본 | 결과 |
|---|---|---|
| 초급 [🔄 다른 도움 받기] | 업무 중간보고 t2: 처음(빈칸이 문장 끝 → 실패) → 다시 받음 "장소에 문제가 있어요. 의자가 없어요." | 합격 — 다시 받기로 회복 |
| 〃 | 회의 반대 의견 t2: 처음 "자료도 회의실에서 보여 줘요"(질문과 맞지 않음) → 다시 받음 "네. 신문 광고도 해요."(명사 겹침, partial 약함) | 불합격 — 두 번 모두 미달 |
| 카드 난이도별 복습 채점 | 같은 답을 초급·고급 카드로 채점 | 둘 다 ✅(다른 적절한 표현). 고급은 하십시오체 해설, 초급은 해요체 짧은 해설 + 영어 병기(1차에는 영어 줄이 빠져 형식 칸에 초급 예를 넣은 뒤 해결) |
| 문장마다 길이 적용 | 회의 반대 의견·중급 model | 첫 문장 9어절(최대 7)로 문장마다 세어도 초과 — 화면은 1회 다시 받은 뒤 표시 |
| 맞는 문장은 잘한 점으로 | 초급·업무 중간보고 피드백 | 합격 — "고칠 표현이 없어요", 다음 문장도 초급 문형 |
| 〃 | 초급·회의 반대 의견 피드백 | 불합격 — "우리 손님은 나이가 많아요"를 뜻 차이를 이유로 다시 지적 |
| 〃 | 중급·회의 반대 의견 피드백 | 불합격 — "좋겠어요" → "좋을 것 같아요"(완곡 겹치기), 다음 문장 10어절 |
| 초급 해설 어휘 | 초급 피드백 2개 | 해설 줄은 초급 어휘·짧은 문장으로 바뀜(1차에 남았던 '-아/어 볼게요'는 2차에 해결) |

- 화면 안전장치 추가: 원래 표현에서 낱말을 빼기만 한 "고침"(예: "우리 손님은…" → "손님은…")은 노트 후보에서 버림. 노트 체크박스는 처음에 비어 있어 학습자가 직접 고름.
- 전체 64개 표본 판정은 59 합격 / 5 불합격으로 그대로(불합격 표본은 같은 5개).

## 초급 starter 도움 실패 원인 확인 (fix-beginner-support, API 9회)

`scripts/support-check.mjs`로 화면(RoleplaySupportPanel)과 같은 순서(구조 검증 → replyTo → 초급 범위 → 반복)로 분류함. 이 작업의 호출은 기존 누적 카운터와 따로 셈(eval-out/_calls-fix-beginner.json).

### 재현: 거래처 미팅 연기 요청 · 초급, "네, 안녕하세요. 무슨 일이세요?" 다음 차례 (3회)

| 회 | 분류 | 내용 |
|---|---|---|
| 1 | 구조: schema | 문장 틀의 빈칸이 문장 끝에 있음 |
| 2 | 길이 검사 | "네, {{1}} 미팅을 {{2}} 미뤄야 해요." 6어절(최대 5) |
| 3 | 길이 검사 | "내일 오전 미팅을 다음 주로 미뤄야 해요." 7어절(최대 5) |

- 화면에서는 starter 2회 실패 → 대체 경로(frame·choices 따로)까지 가서 "도움을 불러오지 못했어요."가 됨.
- "미팅", "다음 주"는 위 단계 명사 목록에 없어 어휘 검사에는 걸리지 않음. 이 턴의 주원인은 **길이 검사**(장면 내용을 다 담으려다 5어절을 넘김)와 구조 실패.
- 덧붙여 '-아/어야 하다'(4권)가 초급 문장에 나왔지만 현재 검사가 잡지 못함.

### 수정 후 확인 (화면과 같은 흐름, API 10회)

`scripts/support-check.mjs app`: 처음 받기 → (구조 실패이거나 난이도 위반이 있으면) 1회 다시 받기 → 위반이 적은 쪽 → 구조 실패가 이어지면 대체 경로.

| 실행 | 1차 수정 후 (6회) | 2차 수정 후 (4회) |
|---|---|---|
| 거래처 미팅 연기 · 초급 "무슨 일이세요?" 차례 ① | 표시(길이 위반 → 다시 받아 위반 0). intent "전화한 용건을 말하기"로 사과 단계가 빠짐 | 표시, 위반 0: "죄송해요. 미팅을 다음 주로 미뤄도 괜찮으세요? 내부 사정이에요." |
| 같은 차례 ② | **오류** — 구조 실패 3번(틀–정답 불일치 → 같은 보기 → 대체 경로 빈칸 개수) | 표시: "죄송해요. 내부 사정이 있어요. 미팅을 다음 주로 미루고 싶어요." 남은 위반 1건은 반말 보기의 "죄송해."를 한 마디로 세지 않은 검사기 빈틈 → 고침 |
| 회의 일정 조율 · 첫 대사 | 표시, 위반 0이지만 "출장에 회의가 있어요"(뜻이 맞지 않음) | 표시, 위반 0: "출장이 있어요. 금요일에 회의 시간을 바꿔요." |

- 2차 수정: 용건을 묻는 차례는 intent에 목표의 첫 단계부터 순서대로 쓰고 문장 틀·정답 보기도 첫 단계로 시작 / 핵심 어휘는 뜻에 맞는 자리에만 / 대체 경로에서 문장 틀·보기 중 하나만 받아도 그것을 표시.
- 남은 점: intent 문구 자체에는 '사과'가 들어가지 않고 "미팅을 미루자고 말하고 사유 설명하기"처럼 나옴(도움 문장은 "죄송해요."로 시작함). "미뤄도 괜찮으세요?"의 '-아/어도 괜찮다'는 4권 문형과 가까우나 검사 대상이 아님.
- 이 작업 API: 원인 확인 9회 + 수정 후 확인 10회 = 19회(기존 누적 카운터와 별도). 429 없음.

## 롤플레이 대화 종료 처리 원인 확인 (fix-roleplay-ending)

- 장치 점검: 프롬프트에는 "학습자 발화가 8번을 넘으면 마무리 + '(대화를 마치려면 피드백 받기 버튼을…)' 안내" 규칙(prompts.ts 대화 진행 규칙 6) 하나뿐. 목표 단계 완료·끝인사 교환을 판단하는 규칙, 종료 표시, 화면의 종료 상태·반복 감지는 없음. 그래서 상대역이 끝인사를 되풀이해도 대화가 계속되고 도움 패널도 계속 요청함.
- 재현(API 1회, `scripts/ending-check.mjs repro`, 거래처 미팅 연기 · 초급, 목요일 오전 10시로 정하고 끝인사를 두 번 주고받은 뒤 차례): **구조 실패 — schema: 문장 틀의 빈칸이 문장 끝**. 문장 틀이 "네, {{1}}."(빈칸 = 감사 인사)로 나옴. 끝인사에는 빈칸으로 둘 명사(날짜·장소 등)가 없어 인사말 전체를 빈칸으로 만든 것. 이 오류는 다시 받지 않고 바로 대체 경로로 가며, 대체 경로의 문장 틀도 같은 이유로 실패하기 쉬워 "도움을 불러오지 못했어요."가 됨.
