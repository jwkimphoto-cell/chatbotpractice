# 「오피스 한국어 코치」 웹앱 확장 명세

## 0. 목표
현재의 "직장 한국어 연습 도우미"(표현 소개 → 빈칸 퀴즈 → 채점)를 그대로 유지하면서, 아래 3가지 기능을 더해 「오피스 한국어 코치」 웹앱으로 확장한다.
① 상황 롤플레이: 장면 카드를 고르면 AI가 상사·동료·거래처 역할로 대화를 이어 가고, 대화가 끝나면 피드백을 준다.
② 이메일 첨삭: 받는 사람과 목적에 비추어 높임법·완곡 표현·결론 먼저 쓰기를 점검하고, 고친 예시를 보여 준다.
③ 나의 표현 노트: ①②에서 지적받은 표현과 고친 표현을 모아 복습 카드로 만들고, 정해진 간격으로 다시 퀴즈를 낸다.

대상: 한국 기업 취업을 준비하는 중·고급 외국인 학습자, 입사 초기 외국인 직장인
학습 목표: 문법 정확성보다, 상대(상사·동료·거래처)와 상황에 맞는 표현 선택(높임법, 완곡 표현, 보고 순서)을 스스로 점검하게 하는 것

## 1. 관련 파일
- src/components/Chatbot.tsx: 기존 표현 연습 화면(주제→난이도 2단계 버튼, 스트리밍 표시, 오류 배너)
- src/components/FormattedMessage.tsx: 메시지 마크다운 렌더링
- src/api/chat.ts: streamChatMessage() — /api/chat로 SSE 스트리밍 요청
- api/chat.ts: Vercel 서버리스 핸들러, OpenAI Responses API 호출
- vite.config.ts: 개발 서버에서 /api/chat만 api/chat.ts로 연결하는 플러그인

## 2. 바꾸지 말아야 할 것 (제약 조건)
1. API 키 처리 방식(서버에서 process.env.OPENAI_API_KEY 사용, .env.local)은 그대로 둔다. 키를 프런트엔드로 보내거나 NEXT_PUBLIC_/VITE_ 접두사 변수로 바꾸지 않는다.
2. 모델명, reasoning 설정, 스트리밍(SSE) 응답 방식은 그대로 둔다.
3. 기존 표현 연습 기능의 동작과 WORKPLACE_KOREAN_SYSTEM_PROMPT의 내용은 바꾸지 않는다.
4. 엔드포인트는 /api/chat 하나만 쓴다(vite.config.ts 개발 플러그인이 /api/chat만 연결함).
5. 기존 UI 스타일(색상, 버튼 모양, 말풍선, 오류 배너)을 재사용한다.
6. 새 라이브러리(라우터, 상태관리, UI 키트 등)는 설치하지 않는다. 탭 전환은 React state로 구현한다.
7. 서버·DB는 추가하지 않는다. 표현 노트는 브라우저 localStorage에 저장한다.

## 3. 전체 화면 구조
- 헤더 제목: "💼 오피스 한국어 코치", 부제: "보고·회의·이메일 장면에서 대화하고, 쓰고, 피드백 받는 직장 한국어 연습"
- 탭 4개: [표현 연습] [상황 롤플레이] [이메일 첨삭] [나의 표현 노트 ●N] (●N = 오늘 복습할 카드 수, 0이면 숨김)
- 탭을 바꿔도 각 탭의 대화 내용과 입력 상태는 유지한다.
- 스트리밍 중에는 탭 전환 버튼을 비활성화한다.
- 헤더의 "대화 초기화" 버튼은 현재 탭만 초기화한다.
- 375px(모바일) 폭에서도 탭과 입력창이 깨지지 않는다.
- 서버 전용 프롬프트·장면 데이터는 api/_lib/에 둔다(밑줄: Vercel이 별도 함수로 배포하지 않음). import는 './_lib/prompts.js'처럼 .js 확장자를 붙인다. src와 api 사이에는 서로 import하지 않는다.

## 4. API
1. 요청 본문: { mode, sceneId?, messages } — mode: 'expression' | 'roleplay' | 'email' | 'review', 없으면 'expression'.
2. mode 허용 목록 검사, 아니면 400.
3. mode별 instructions: expression=기존 프롬프트 / roleplay=공통 프롬프트+서버 장면 설정(sceneId 없거나 목록에 없으면 400) / email=EMAIL_COACH / review=REVIEW_GRADER
4. 장면 설정과 시스템 프롬프트는 서버에서만 조립한다. 클라이언트 텍스트를 instructions에 넣지 않는다.
5. messages 최대 40개, 메시지당 최대 4,000자. 넘으면 400 + 한국어 오류 메시지.
6. streamChatMessage(messages, onDelta, options?)에 { mode?, sceneId? } 추가, 기존 호출부 호환.

## 5. 응답 끝 메타 블록 규약
- 노트용: [[NOTES]] JSON 배열 [[/NOTES]] — 항목 필드: scene, counterpart, original, corrected, category("높임법"|"완곡 표현"|"보고 순서"|"어휘·문법"), reason. 고칠 표현이 없으면 []. 코드 펜스 없이 JSON만.
- 채점용: [[RESULT]]{"correct":true}[[/RESULT]]
- 화면 표시 시 마커부터 끝까지 숨김. 스트리밍 중 마커 일부("[[NO" 등)로 끝나는 꼬리도 숨김.
- 스트리밍 종료 후 JSON.parse + 필드 검증. 실패하면 저장 버튼을 보여 주지 않고 조용히 넘어감.
- 대화 기록을 다시 보낼 때도 메타 블록 제거.

## 6. 상황 롤플레이
### 흐름
1. 장면 카드 그리드(제목, 상대, 한 줄 상황, 연습 목표)
2. 카드 선택 → [중급] [고급] + "← 장면 다시 선택"
3. 난이도 선택 → "장면 · 상대 · 목표" 요약 바 고정, 첫 대사를 장면 데이터에서 즉시 표시(API 호출 없이 assistant 메시지로 기록)
4. 학습자 입력 → mode:'roleplay', sceneId 전송. 첫 사용자 메시지에 "[난이도: 중급]" 포함
5. [피드백 받기] 버튼 → "[피드백 요청] 대화를 마치고 피드백을 주세요." 전송
6. 피드백 후 NOTES 체크박스 목록(기본 전체 선택) + [선택한 표현 노트에 저장], 저장 후 "표현 노트에 N개 저장했어요". 자동 저장 금지.
### 장면 (id / 제목 / 상대 / 상황 / 목표 / 첫 대사) — 회사·인물은 가상
1. report-delay / 일정 지연 보고 / 김 팀장(직속 상사) / 금요일까지 내기로 한 시장 조사 보고서가 자료 수집 지연으로 다음 주 화요일로 늦어질 것 같음 / 결론(지연) → 원인 → 대책·새 일정 / "지금 잠깐 괜찮아요? 지난주에 맡긴 시장 조사 보고서는 어떻게 되고 있어요?"
2. report-progress / 업무 중간보고 / 김 팀장 / 행사 준비 약 70% 진행, 장소 계약에 문제 하나 / 핵심 먼저, 수치로 짧게 / "이번 행사 준비 진행 상황 좀 간단히 말해 줄래요?"
3. meeting-disagree / 회의에서 반대 의견 부드럽게 말하기 / 박 과장(회의 진행자) / SNS 광고로만 홍보하자는 제안에 예산·주 고객층 문제로 다른 의견 / 상대 의견 인정 → 완곡한 반대 → 근거 → 대안 / "그럼 이번 홍보는 SNS 광고로만 진행하는 걸로 정리할게요. 다른 의견 있으세요?"
4. meeting-schedule / 회의 일정 조율 / 이 대리(다른 팀 동료) / 목요일 오후 회의에 출장으로 참석 어려움 / 사정 설명 + 대안 시간 제시 / "목요일 오후 2시 회의 초대 보냈는데 확인했어요?"
5. client-postpone / 거래처 미팅 연기 요청(전화) / 최 부장(거래처 한빛상사) / 내일 오전 미팅을 내부 사정으로 다음 주로 / 사과 → 간단한 사유 → 대안 일정 → 양해 구하기 / "네, 한빛상사 최민수입니다."
6. colleague-request / 다른 부서에 자료 협조 요청 / 정 대리(재무팀) / 분기 예산 자료 필요, 상대도 바쁜 시기 / 쿠션어 + 구체적 요청(무엇을, 언제까지) / "네, 재무팀 정하나입니다. 무슨 일이세요?"
### ROLEPLAY 프롬프트 요구사항
- 대화 중에는 상대역으로만 말한다. 한 번에 1~3문장, 사내 구어처럼. 중급은 짧고 쉽게, 고급은 실제에 가깝게.
- 빠진 정보는 역할 안에서 되묻는다("원인이 뭔가요?", "그럼 언제까지 가능해요?").
- 대화 중에는 고쳐 주지 않는다. 못 알아들으면 "죄송한데, 다시 한번 말씀해 주시겠어요?"
- 학습자가 영어로 묻거나 도움을 청하면 "(도움말) …" 한 줄 후 역할로 복귀.
- 학습자 발화 8번 초과 시 자연스럽게 마무리 + "(대화를 마치려면 '피드백 받기' 버튼을 눌러 주세요.)"
- "[피드백 요청]"을 받으면 아래 형식으로만 피드백:
  ## 롤플레이 피드백 / **장면:** · **상대:** / ### 잘한 점(1~2개, 학습자 발화 인용) / ### 다시 생각해 볼 표현(최대 3개: 내가 한 말 / 더 알맞은 표현 / 이유: [범주] — 상대·상황 근거) / ### 말하기 순서 점검 / ### 다음에 써 볼 한 문장 / [[NOTES]]…[[/NOTES]]

## 7. 이메일 첨삭
### 흐름
1. 폼: 받는 사람(팀장(상사)/같은 팀 동료/다른 부서 동료/거래처 담당자/고객), 목적(요청/일정 변경·연기/사과/보고/감사/거절), 상황 메모(선택, 100자), 제목, 본문(필수, 2,000자, 글자 수 표시)
2. [첨삭 받기] → "[이메일 첨삭 요청]\n받는 사람: …\n목적: …\n상황 메모: …\n제목: …\n본문:\n…" 형식으로 mode:'email' 전송
3. 결과 아래에서 추가 질문 채팅 가능
4. NOTES 저장 UI(롤플레이와 동일)
5. [새 이메일 쓰기]로 폼 초기화
### EMAIL_COACH 프롬프트 요구사항
- 우선순위: 높임법 > 완곡 표현 > 결론 먼저 쓰기 > 문법(사소한 문법 오류는 최대 1개만 언급)
- 학습자 내용·의도 유지, 잘 쓴 부분은 바꾸지 않음
- 없는 사실(날짜·금액·이름)은 지어내지 않고 [날짜], [담당자명] 자리표시
- 거래처·고객은 하십시오체 기본, 사내 동료는 해요체 허용
- 본문이 너무 짧으면 더 써 달라고 안내, NOTES는 []
- 출력: ## 첨삭 결과 / **받는 사람:** · **목적:** / ### 한눈에 보기(높임법·완곡 표현·결론 먼저 쓰기 각각 ✅/⚠️/❌ + 한 줄) / ### 고칠 부분(최대 5개: 원문 / 고친 표현 / 이유: [범주] — 근거) / ### 고친 예시(제목+본문 전체, 고친 곳 **굵게**) / [[NOTES]]…[[/NOTES]]
- 예: "내일까지 보내 주세요" → "번거로우시겠지만 내일까지 보내 주시면 감사하겠습니다"

## 8. 나의 표현 노트
### 저장
- localStorage 키 "officeKoreanCoach.notes.v1", 읽기·쓰기 try/catch, 실패 시 빈 목록
- NoteCard: id, createdAt, source('roleplay'|'email'), scene, counterpart, original, corrected, category, reason, box(0~4), nextReviewAt, reviewCount, lastResult?
- original+corrected 중복 저장 금지, 최대 500장
- 복습 간격: box 0→1일, 1→3일, 2→7일, 3→14일, 4→30일. 새 카드 box 0(+1일). 정답 box+1(최대 4), 오답 box 0(다음 날)
### 화면
- 요약(전체 N장 · 오늘 복습 M장), [오늘 복습 시작(M)] [전체 복습]
- 필터: 출처, 범주
- 카드: "장면 · 상대", 원래 → 고친 표현, 이유, 다음 복습일, [삭제](window.confirm 대신 인라인 확인)
- 빈 상태 안내 + 롤플레이·이메일 탭 이동 버튼
### 복습 퀴즈
1. 문제는 API 호출 없이 로컬 생성:
   복습 카드 (3/5) / 상황: [scene] · 상대: [counterpart] / Q. 아래 표현을 상황에 더 알맞게 고쳐 써 보세요. / "[original]" / 힌트: [category]을(를) 생각해 보세요. / 답을 입력해 보세요. (힌트에 corrected 노출 금지)
2. 제출 → mode:'review'로 "[복습 채점 요청]\n장면: … / 상대: … / 원래 표현: … / 모범 표현: … / 범주: … / 학습자 답: …"
3. REVIEW_GRADER: 글자가 달라도 의미 유지 + 범주 기준 충족이면 정답, 띄어쓰기·문장부호 무시. 출력: 결과: 정답이에요!/아쉬워요. / 모범 표현: … / 해설: 1~2문장 / [[RESULT]]{"correct":true}[[/RESULT]]
4. RESULT로 box·다음 복습일 갱신 → [다음 카드] → 마지막 요약("5장 중 4장 정답 · 다음 복습: 11월 22일")
5. API 오류나 RESULT 파싱 실패 시 [정답 보기] → [맞혔어요] [다시 볼래요] 자기 채점

## 9. 모든 AI 프롬프트 공통 피드백 원칙
1. 근거는 상대·장면·목적으로 설명한다. "한국인은 원래…", "외국인은 보통…" 같은 국적·문화 범주 단정 금지.
2. 관례는 "이 상황에서 이렇게 말하면 더 정중하게 들린다/오해를 줄인다"처럼 사용 효과로 설명하고, 가치관 동의를 요구하지 않는다(이해·사용·동의 구분).
3. 문법보다 표현 선택(높임법·완곡 표현·보고 순서) 우선.
4. 칭찬은 구체적으로, 과장 금지.
5. 지적 개수 상한(롤플레이 3, 이메일 5).
6. 중·고급 학습자가 이해할 쉬운 한국어.
7. 학습자가 말하지 않은 사실은 지어내지 않는다.

## 10. 완료 기준
